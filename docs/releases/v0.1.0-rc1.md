# Bashloom 0.1.0-rc1

## English

This is the first public release-candidate baseline for Bashloom `v0.1.0`, frozen for multi-consumer field validation.

### Highlights

- Dependency-free Bash runtime for reliable shell applications and system automation.
- argv-safe command execution with exact exit-status preservation and dry-run support.
- Reliability primitives for retry, wait, timeout, cleanup, rollback and transactions.
- Filesystem and idempotency helpers, atomic replacement, locking, checksums, XDG/path helpers and change tracking.
- Human/plain/JSON output, logging, diagnostics, config and persistent state.
- Selective dependency-aware loader and pinned vendoring with offline SHA-256 integrity verification.
- Git, systemd, Docker Compose, network and optional APT integrations.
- Terminal UX with prompts, selections, progress, spinners, panels, tables and topology-aware trees.
- Theme/style registry, multiple visual variants, width-aware Unicode rendering and deterministic ASCII/CI fallbacks.
- Dependency-light full-screen TUI foundation with alternate-screen lifecycle, cursor control, terminal sizing and key normalization.
- Permanent public API documentation parity gates for English and Italian.

### RC semantics frozen for validation

- `blm_timeout` uses GNU coreutils `timeout` for external executables when available, while shell functions/builtins retain the Bash-compatible fallback.
- Numeric permission modes are validated before filesystem mutation.
- `blm_ensure_line` rejects multiline payloads.
- JSON escaping covers all C0 controls representable by Bash variables.
- `blm_atomic_write` guarantees same-filesystem atomic replacement, not fsync/power-loss durability.
- Directory locks do not perform automatic stale-lock recovery.
- `BLM_LOG_FILE` never creates parent directories implicitly.

### Validation

The RC release pipeline passed syntax checks, ShellCheck, shfmt, source-documentation contract, EN/IT public-API documentation contract, Bats tests and maintained examples/full-tour.

## Italiano

Questa è la prima baseline release candidate pubblica di Bashloom `v0.1.0`, congelata per la validazione sul campo multi-consumer.

### Novità principali

- Runtime Bash dependency-free per applicazioni shell affidabili e automazione di sistema.
- Esecuzione comandi argv-safe con preservazione esatta degli exit status e supporto dry-run.
- Primitive di reliability per retry, wait, timeout, cleanup, rollback e transazioni.
- Helper filesystem e idempotenza, sostituzione atomica, locking, checksum, helper XDG/path e change tracking.
- Output human/plain/JSON, logging, diagnostica, config e stato persistente.
- Loader selettivo dependency-aware e vendoring pinnato con verifica integrità SHA-256 offline.
- Integrazioni Git, systemd, Docker Compose, network e APT opzionale.
- Terminal UX con prompt, selezioni, progress, spinner, panel, table e tree topology-aware.
- Registry theme/style, varianti visuali multiple, rendering Unicode width-aware e fallback deterministici ASCII/CI.
- Foundation TUI full-screen dependency-light con lifecycle alternate-screen, controllo cursore, dimensionamento terminale e normalizzazione tasti.
- Gate permanenti di parità documentale delle API pubbliche tra inglese e italiano.

### Semantiche RC congelate per la validazione

- `blm_timeout` usa GNU coreutils `timeout` per gli eseguibili esterni quando disponibile, mentre funzioni shell e builtin mantengono il fallback compatibile Bash.
- I permission mode numerici vengono validati prima delle mutazioni filesystem.
- `blm_ensure_line` rifiuta payload multilinea.
- L'escaping JSON copre tutti i controlli C0 rappresentabili dalle variabili Bash.
- `blm_atomic_write` garantisce sostituzione atomica sullo stesso filesystem, non durabilità fsync/power-loss.
- I directory lock non effettuano recovery automatico degli stale lock.
- `BLM_LOG_FILE` non crea mai implicitamente le directory parent.
